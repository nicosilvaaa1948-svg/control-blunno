No se usan custom claims: el rol se determina por el correo exacto.

1) FIREBASE AUTHENTICATION
Firebase Console → Authentication → Users → crear las 5 cuentas con Email/Password.
Las contraseñas las definís vos. No están guardadas en este proyecto.

2) FIRESTORE + STORAGE RULES
Desde la carpeta de este proyecto, con Firebase CLI autenticado y el proyecto seleccionado:
  firebase deploy --only firestore:rules,storage

El archivo firebase.json ya apunta a:
- Firestore: firebase.rules
- Storage: storage.rules

3) WEB
Subir el contenido de esta carpeta a GitHub Pages, conservando index.html como entrada.
La web usa Firebase 12.3.0 desde gstatic.com y no necesita node_modules para GitHub Pages.

4) PERFILES
Las 4 cuentas Generales tienen acceso total.
La cuenta horas@gmail.com puede entrar solamente a Personal y Horas mensuales; puede crear empleados y cargar/corregir horas, pero no totaliza ni modifica/elimina liquidaciones, no elimina empleados y no puede usar otros sectores.

5) SESIONES SIMULTÁNEAS
Las 5 cuentas pueden tener sesiones abiertas al mismo tiempo. Cada sesión recibe su perfil según el correo con el que inició sesión.

6) DESPUÉS DE PUBLICAR
Cerrar sesión y volver a entrar después de publicar las reglas para que la sesión use la versión actual.

NOTA
Este paquete está preparado y probado localmente. La creación de las 5 cuentas y el deploy remoto de reglas requieren acceso al proyecto Firebase desde tu propia consola/CLI.
